# 家校协同成绩洞察平台 后端模块划分与实施顺序 V1

更新日期：2026-06-15  
用途：后端启动、接口分工、开发优先级说明

## 1. 目标

在当前教师端原型基础上，启动后端骨架设计，目标不是一次做完所有能力，而是：

- 先支撑班主任独立建班和导入成绩
- 先支撑考试与成绩模块的数据闭环
- 让教师端逐步从本地状态迁移到接口驱动

## 2. 推荐后端模块

### 2.1 账号与身份模块
- 用户注册登录
- 老师 / 家长 / 学生账号绑定
- 微信小程序身份识别

### 2.2 学校组织模块
- 学校
- 年级
- 行政班
- 教学班
- 老师角色与范围

### 2.3 学生档案模块
- 学生基础档案
- 家长联系方式
- 选科组合
- 学生选科关系

### 2.4 考试与成绩模块
- 考试
- 考试学科配置
- 成绩导入批次
- 成绩明细
- 成绩聚合

### 2.5 分析模块
- 总分聚合
- 排名计算
- 分层结果
- 分析快照

### 2.6 预警模块
- 学校模板规则
- 班主任个性规则
- 学生预警结果

### 2.7 同步通知模块
- 通知任务
- 通知回执
- 渠道状态

### 2.8 展示策略模块
- 学校上限策略
- 班级展示策略

## 3. 第一阶段必须先做的模块

优先级按真实可用顺序：

1. 学校组织模块  
2. 学生档案模块  
3. 考试与成绩模块  
4. 分析模块  
5. 展示策略模块  
6. 同步通知模块  
7. 预警模块

## 4. 当前最适合先打通的业务流

### Flow A：班主任快速起盘
- 老师注册
- 创建班级
- 导入学生档案
- 维护家长信息

### Flow B：考试与成绩闭环
- 创建考试（后端存在，前端导入时隐式创建）
- 导入成绩文件
- 校验导入结果
- 保存成绩明细
- 计算聚合结果
- 返回考试详情

### Flow C：分析输出
- 获取班级总览
- 获取考试成绩表
- 获取异常与预警结果

## 5. 接口优先级建议

### P0 接口
- `POST /api/classes`
- `POST /api/students/import`
- `GET /api/classes/:id/students`
- `POST /api/exams/import`
- `GET /api/exams`
- `GET /api/exams/:id`
- `PATCH /api/exams/:id/scores/:scoreId`

### P1 接口
- `GET /api/classes/:id/teachers`
- `POST /api/classes/:id/teachers`
- `PATCH /api/classes/:id/teachers/:teacherId`
- `GET /api/classes/:id/display-policy`
- `PATCH /api/classes/:id/display-policy`

### P2 接口
- `GET /api/exams/:id/analysis`
- `GET /api/exams/:id/alerts`
- `POST /api/notifications/tasks`

## 6. 与当前教师端的对齐方式

当前教师端已经具备的可迁移页面：
- 班级与师生
- 考试与成绩
- 分析与预警
- 同步中心

建议迁移顺序：
- 先把 `班级与师生` 和 `考试与成绩` 变成接口驱动
- 再迁移 `分析与预警`
- 最后迁移 `同步中心`

## 7. 当前后端重点

如果现在只做一件最值的事，应该是：

**先把考试与成绩模块做出来。**

原因：
- 它是整个系统最核心的数据入口
- 它决定后续分析是否真实可用
- 当前教师端对这块已经有较完整原型，适合前后端对齐落地

## 8. 建议的最近实施顺序

### Sprint 1
- 落地 SQL 初稿
- 建最小后端骨架
- 实现学生档案 CRUD
- 实现考试列表与考试详情

### Sprint 2
- 实现成绩导入批次保存
- 实现成绩明细保存
- 实现基础校验结果返回

### Sprint 3
- 实现总分聚合
- 实现成绩修改后的重算
- 教师端切到接口驱动

## 9. 当前结论

当前已经具备开始后端的条件：
- 产品范围明确
- 数据模型核心方向稳定
- 教师端页面骨架已足够支撑接口落地

下一步最合理的是：
- 以后端骨架开始
- 优先实现考试与成绩模块
- 教师端同步迁移到真实接口
